# E-commerce Analytics Project

Учебный проект по аналитике данных: от проектирования базы данных до SQL-анализа, обработки данных в Python, визуализации и A/B-тестирования. 

Цель — построить законченный сквозной pet-проект, отрабатывая на нём методологию, применимую к реальной аналитической работе.

## Статус проекта

- **Завершено:** проектирование БД, генерация данных, SQL-анализ (оконные функции, CTE, RFM-сегментация, оптимизация запросов).
- **В процессе:** переход к анализу данных в Python (pandas).
- **Впереди:** статистика, визуализация, A/B-тестирование, автоматизация.

## Данные

Данные полностью синтетические, сгенерированы через Python (Faker) и намеренно частично искажены (дубликаты, пропуски, аномалии) — датасет имитирует структуру 
и проблемы реальной e-commerce базы, а не отражает существующий бизнес. 

Такой подход выбран специально: он даёт полный контроль над структурой данных и 
позволяет осознанно тренироваться на типичных проблемах реальных данных (очистка, обработка пропусков, аномалий), а не работать с уже идеальным датасетом.

## Инструменты

- **СУБД:** PostgreSQL, администрирование через pgAdmin
- **Язык:** Python 3 (виртуальное окружение), редактор — VS Code
- **Библиотеки:** pandas, SQLAlchemy, Faker, python-dotenv
- **Планы:** matplotlib/seaborn/plotly, Metabase (BI), scipy/statsmodels (статистика)

## Схема данных

Смоделирован интернет-магазин из пяти связанных таблиц:
customers --< orders --< order_items >-- products
                  |
                  --< payments

- `customers` — клиенты (email уникален, телефон и город — необязательные поля)
- `products` — товары с себестоимостью и ценой продажи
- `orders` — заказы со статусом (completed / shipped / cancelled / refunded)
- `order_items` — позиции заказа; цена фиксируется на момент покупки отдельно от текущей цены товара (защита от искажения исторических данных при изменении цен)
- `payments` — платежи; отсутствуют для отменённых заказов

Полная схема с обоснованием типов данных и constraints — в `sql/create_tables.sql`.

## Пройденные темы (SQL)

- Оконные функции: ROW_NUMBER, RANK, DENSE_RANK, LAG, NTILE, SUM/COUNT OVER
- CTE, включая множественные и рекурсивные (generate_series)
- Когортный анализ, retention, RFM-сегментация клиентов
- Чтение планов выполнения (EXPLAIN ANALYZE), Seq Scan vs Bitmap/Index Scan, влияние индексов на производительность
- Перевод неоднозначных бизнес-формулировок в конкретные технические требования

## Следующие шаги

1. Python/pandas: те же аналитические задачи, что решены в SQL, — для сравнения подходов и наработки навыка работы с DataFrame
